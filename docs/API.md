# FitTrack AI — REST API Contract

Base URL: `http://localhost:8000` (configurable). All JSON. All routes are prefixed with `/api`.
Interactive docs (auto-generated by FastAPI): `http://localhost:8000/docs`.

Conventions
- Dates are `YYYY-MM-DD`, times are `HH:MM` (24h), timestamps are ISO-8601.
- Numbers are kcal / grams unless the field name says otherwise.
- Errors: `{"detail": "message"}` with a non-2xx status.
- Uploaded files are served from `/uploads/<path>` (the `*_url` fields are relative, e.g. `/uploads/food/abc.jpg`).
- The app is single-user (user id 1). There is no login; run it on a private machine/network.

## History & assistant

| Method | Path | Body | Returns |
|---|---|---|---|
| GET | `/api/history?page=1&page_size=10&q=&start=&end=&workout=&split=&balance=&status=&weighed=&sort=date&order=desc` | – | `HistoryPage` |
| GET | `/api/assistant/suggestions` | – | `{suggestions: string[]}` |
| POST | `/api/assistant/chat` | `ChatRequest` | `ChatAnswer` (both turns are stored) |
| GET | `/api/assistant/conversations` | – | `Conversation[]` (newest first) |
| GET | `/api/assistant/conversations/{id}` | – | `{id, messages: StoredMessage[]}` |
| POST | `/api/assistant/import` | `{messages: [{role, content, meta?, created_at?}]}` (max 500) | `{conversation_id, imported, skipped}` (same conversation twice = skipped) |

History lists every day with something logged (food, training, weigh-in, check-in or symptom) plus today, newest first.
The detail of a row is `GET /api/daily/{date}`.
- `q`: words that must all appear in the day's foods, ingredients, meal names, exercises, muscles, splits, symptoms, notes, weekday or date
- `workout`: `"any"|"trained"|"rest"`, `split`: one `split` value, `balance`: `"any"|"deficit"|"surplus"|"pending"`,
  `status`: `"any"|"critical"|"warning"|"ok"` (worst alert of the day), `weighed`: `true|false`
- `sort`: `"date"|"calories"|"protein"|"deficit"|"weight"|"exercise"`, `order`: `"asc"|"desc"`; `page_size` 5–100; range defaults to start date → today (max 366 days)

`HistoryPage` = `{items: HistoryRow[], total, page, page_size, pages, range: {start, end}, summary: HistorySummary}`

`HistorySummary` (over every matching day, not just the page)
```
days, food_days, trained_days, avg_calories|null, avg_protein|null, avg_deficit|null, weigh_ins, weight_change|null,
series: [{date, calories|null, protein|null, deficit|null, weight|null}] (date order, last 90 days)
```

`HistoryRow`
```
date, day_number, weekday, is_today, is_rest_day, complete, morning_weight, weight_change (vs previous weigh-in),
total_calories, total_protein, total_carbs, total_fat, protein_per_kg, estimated_exercise_calories, estimated_tdee,
calorie_deficit (number|null), deficit_status, food_count, foods_preview: string[],
workout: {splits: string[], lifting_min|null, cardio_min|null, exercise_count, exercises_preview: string[]},
energy_level, sleep_hours, mood, bloating_status, steps,
status ("critical"|"warning"|"ok"), alerts_count, top_alert|null
```

`ChatRequest` = `{message (1–1000 chars), history: [{role: "user"|"assistant", content}] (max 20, last 8 used), conversation_id?}`
— with `conversation_id` the earlier turns are read from the database (and `history` is ignored); without it a new
conversation starts. Chats are stored in `assistant_messages`; "New chat" never deletes anything.

`Conversation` = `{id, title (first question), started_at, updated_at, messages}`;
`StoredMessage` = `{id, role, content, meta (assistant turns: the ChatAnswer fields except answer), created_at}`

`ChatAnswer`
```
answer (Markdown: **bold**, ### headings, bullet lists, | tables |), mode ("ai"|"offline"), provider|null, model|null,
basis ("Based on 3 complete logged days · 3 weigh-ins"), asked_dates: date[], suggestions: string[] (follow-ups),
notice? (only offline: why there was no AI answer), conversation_id, question_id, answer_id
```
Every number is computed from the logs first (averages, weight trend, energy-balance projections at 7,700 kcal/kg —
a constant-deficit and an adaptive model where burn falls with body weight — and the full log of any day the question
mentions: "yesterday", "1 week ago", "last monday", "26 oct", "26/10", "day 2"), plus gaps to the protein / calorie
/ weight targets. The LLM only explains them: task `fast` first; if its answer contains a number that is not in the facts
(allowing rounding) it is asked again on task `reasoning` (35 s per model). Without a working provider the same facts are
answered by built-in rules (`mode: "offline"`).

## Quick logging: presets, repeat & copy

Goal: a person with a fixed routine logs a normal day in a few taps. All endpoints recompute affected days and refresh the synced xlsx/csv.

| Method | Path | Body | Returns |
|---|---|---|---|
| GET | `/api/presets?kind=workout\|meal` | – | `Preset[]` (most used first) |
| POST | `/api/presets` | `PresetCreate` | `Preset` |
| PUT | `/api/presets/{id}` | partial `PresetCreate` | `Preset` |
| DELETE | `/api/presets/{id}` | – | `{ok}` |
| GET | `/api/presets/{id}/prefill?date=` | – | `{preset, payload}` — payload ready to edit; workout exercises prefilled with **last performance** and a progression suggestion |
| POST | `/api/presets/{id}/apply` | `{date, time?, payload?, scale?}` | `AppliedEntries` |
| POST | `/api/presets/from-day` | `{kind, date, name, meal_type?, icon?}` | `Preset` (snapshot of that day's workout, or of one meal) |
| POST | `/api/days/copy` | `{from_date, to_date, include: ["food","workouts"], meal_types?: string[]}` | `AppliedEntries` |
| POST | `/api/entries/delete` | `{food_ids?: int[], workout_log_ids?: int[], session_ids?: int[]}` | `{ok, deleted}` — used for **Undo** |
| GET | `/api/quick-picks?meal_type=&limit=12` | – | `QuickPick[]` — your most frequent foods for that meal/time, recency-weighted |
| GET | `/api/workouts/last-performance?exercise=` | – | `LastPerformance \| null` |
| GET | `/api/today` | – | `TodayPlan` |

`Preset`
```
id, kind ("workout"|"meal"), name, icon (emoji or lucide name), color|null, split|null, meal_type|null,
payload, use_count, last_used_at|null, created_at,
summary: {calories?, protein?, exercises?, cardio_min?, lifting_min?}
```
`payload` for **workout**:
```
{ session: {split, lifting_duration_min, lifting_met, session_rpe} | null,
  cardio:  [{exercise_name, cardio_duration_min, met_value, rpe}],
  exercises: [{exercise_name, target_muscle, sets, reps, weight_kg, rpe, sets_json}] }
```
`payload` for **meal**:
```
{ meal_type, items: [{food_name, quantity, portion_unit, weight_grams, calories, protein, carbs, fat, fibre,
                      ingredients: string[], tags: string[]}] }
```
`PresetCreate` = `{kind, name, icon?, color?, split?, meal_type?, payload}`

`apply` uses the preset's payload unless `payload` is sent (the edited sheet). `scale` multiplies meal portions (e.g. 0.5, 1.5). Workout exercises whose entry has `"skip": true` are not logged.

`AppliedEntries` = `{food_ids: int[], workout_log_ids: int[], session_ids: int[], summary: string}` — pass the ids to `/api/entries/delete` to undo.

`QuickPick` = `{key, food_name, meal_type, quantity, portion_unit, weight_grams, calories, protein, carbs, fat, fibre, ingredients, tags, times_logged, last_logged}`
(one tap = `POST /api/food` with these values and the chosen date/time).

`LastPerformance` = `{exercise_name, date, sets, reps, weight_kg, rpe, sets_json, suggestion: {weight_kg|null, reps|null, message}}`

`TodayPlan`
```
date, weekday, is_rest_day,
checkin_done: bool, weight_logged: bool,
workout: {split, preset: Preset|null, logged: bool, message},
meals: [{meal_type, label, typical_time, logged: bool, suggested_preset: Preset|null, top_picks: QuickPick[] (≤ 4)}],
protein: {eaten, target}, calories: {eaten, target|null},
next_action: {kind ("checkin"|"meal"|"workout"|"scoop"|"done"), label, meal_type|null}
```
